# AGENTS.md

Инструкции для ИИ-агентов, которые работают с этим репозиторием.

## О проекте

«Расписание ТулГУ по физкультуре» — приложение для составления расписания занятий по физкультуре:
направления (футбол, плавание), преподаватели со ставкой, факультеты, семестры и пары.
Пары одного дня идут для разных факультетов, на них назначаются преподаватели. Полная ставка — 12 занятий в неделю.

Стек: Tauri 2 (Rust) + Svelte 5 (runes) + TypeScript + Tailwind 4. Миграция с Go + Wails завершена, Go-версия не поддерживается.

| Ветка | Что | Статус |
|---|---|---|
| `main` | Tauri 2 + Rust (`src-tauri/`) + Svelte (`frontend/`) | Актуальная версия, здесь вся работа |
| `legacy-go-version` | Go + Wails + Svelte (`backend/`, `frontend/`) | Только справка по прежнему поведению. Не менять |
| `legacy-go-version-win7` | Версия под Windows 7 | Только справка |

## Структура

```
package.json           скрипты: dev, build, check, gen:types, test (через frontend)
pnpm-workspace.yaml    воркспейс: корень + frontend (один lock-файл)
frontend/              Svelte 5 (runes), Tailwind 4, vitest
  src/main.ts          точка входа: шрифты Nunito (@fontsource), стили, i18n, mount
  src/lib/api.ts       адаптер команд Tauri, ответ { data, error }
  src/lib/components/  экраны и компоненты (schedule/, teachers/, directions/, faculties/, ui/)
  src/lib/components/ui/overlay.ts  стек слоёв: Escape закрывает верхний, фокус внутри диалога
  src/lib/stores/      сторы; request.ts переводит коды ошибок через translateError
  src/lib/locales/     ru.json: все тексты интерфейса, включая раздел `errors` (коды бэкенда)
  src/lib/generated/   типы из Rust (ts-rs), не править руками: `pnpm gen:types`
  src/**/*.test.ts     тесты vitest: сторы, request, notify, ключи i18n
src-tauri/
  src/lib.rs           сборка Tauri, состояние, регистрация команд
  src/startup.rs       запуск: конфиг, журнал, база; окно создаётся только после успешного старта; диалоги ошибок
  src/commands.rs      команды (имена повторяют методы Go-версии); ApiResponse { data, error }
  src/schedule.rs      правила расписания, стандартные пары, снятие преподавателя, тесты
  src/storage/db.rs    открытие базы, схема, миграции (таблица app_migrations), резервная копия
  src/storage/repo.rs  SQL-доступ; записи не открывают транзакций сами, их оборачивает вызывающий код
  src/storage/schema.sql  исходная схема (DDL как в Go 0001); дальнейшие изменения — миграциями в db.rs
  src/models.rs        модели (camelCase в JSON)
  src/config.rs        config.json (только dbPath)
  src/error.rs         AppError: код i18n наружу, техническая причина в журнал; тест полноты переводов
  src/logger.rs        журнал действий, сжатие прошлых дней в zip, срок хранения 2 года
  src/archive.rs       упаковка файлов в zip (журналы, резервные копии)
  src/export.rs        экспорт XLSX
  src/win7_compat.rs   хуки delay-load и выбор WebView2 Runtime для Windows 7 (только win7-сборка, см. docs/windows7.md)
  tauri.conf.json      окно (create: false), CSP (csp и devCsp для pnpm dev)
  vendor/wry/          wry 0.57.0 с патчем для Windows 7 (см. vendor/README.md)
```

Логика расписания (лимиты, заглушки, факультеты строки, снятие назначений) — в бэкенде (`src-tauri/src/schedule.rs`).
Фронтенд отображает модель и вызывает команды. Новые команды добавляй и в `commands.rs`, и в `api.ts`
с тем же именем и формой ответа, и в `lib.rs` (регистрация).

## Команды

Всё ставится и запускается из корня. Отдельно `pnpm install` в `frontend/` не нужен: корень — это воркспейс.

- `pnpm install` — установка зависимостей корня и `frontend/`.
- `pnpm check` — `cargo check` + `svelte-check` + `tsc` по конфигам + `vitest` + `vite build`. Основная проверка изменений.
- `pnpm --filter frontend run test` — только тесты фронтенда.
- `cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings` — то же проверяет CI. Сборка без предупреждений.
- `cargo test --lib` — тесты Rust. Запускать из `src-tauri/` (`cd src-tauri && cargo test --lib`): иначе ts-rs создаёт папку `src-tauri/bindings`.
- `pnpm gen:types` — пересборка типов в `frontend/src/lib/generated/` после изменения структур в `src-tauri`. Удалённые типы удаляй из папки вручную, ts-rs их не удаляет.
- `pnpm dev` — запуск окна. **Только по явной просьбе пользователя.** Запускай в открытом диалоге, не в фоне,
  без `timeout`, и дай пользователю остановить процесс. Если нужен запуск, спроси сначала.
- `pnpm build` — сборка приложения (Tauri bundle).
- `pnpm build:win7` — установщик для Windows 7 (WebView2 109 в `src-tauri/WebView2`, см. README). Только по явной просьбе: нужны stable с `rust-src` и WebView2 109 в `src-tauri/WebView2`.
- CI: `.github/workflows/windows.yml` — `pnpm check` и clippy на PR и push в `main`; установщики (NSIS + MSI) и `SHA256SUMS.txt` на теге `v*` публикуются в Releases. Версия тега должна совпадать с `version` в `src-tauri/tauri.conf.json`.
- CI: `.github/workflows/win7-installer.yml` — ручной запуск на `windows-latest` (WebView2 берётся из релиза `webview2-109`, в git его не храним).
- Windows 7: статус, грабли и план — `docs/windows7.md`. Перед любыми изменениями Win7-сборки читать целиком.

## Правила проекта

- **Тесты есть и обязательны для логики.** Rust: правила расписания, миграции, архивация, экспорт, полнота кодов i18n.
  Фронтенд: сторы, `request`, `notify`, ключи i18n. Новое правило расписания или миграция — с тестом.
- **Не коммитить и не создавать ветки** без явной просьбы.
- **Ветку `legacy-go-version` не трогать.** Её используем только как справку по прежнему поведению.
- **Бизнес-логика — в бэкенде** (`src-tauri/src/schedule.rs`, `storage/`). Фронтенд отображает модель и вызывает команды.
- **Ошибки не `panic`.** Бэкенд возвращает `AppResult`/`ApiResponse`. В `error` уходит код-ключ i18n
  (например `errors.teachers.not_found`), его переводит фронтенд (`ru.json`). Технические детали (текст SQLite и т.п.)
  пишутся только в журнал. Новый код ошибки обязан иметь перевод в `ru.json`: тест в `error.rs` это проверяет.
- **Кроссплатформенность.** Код должен работать на macOS, Windows и Linux. Пути — через `std::path` и `dirs`.
- **Windows 7.** Там WebView2 109 (≈ Chromium 109): новый CSS и JS проверять на эту версию. Цвета Tailwind 4 понижаются только в `build:win7` (`frontend/vite.config.ts`).
- **Минимум зависимостей.** Новые крейты и npm-пакеты — только при явной необходимости и с согласием пользователя.
  Уже подключены: `zip` (deflate), `vitest`, `@fontsource/nunito`, `@types/node` (dev, для проверки конфигов).
- **`src-tauri/vendor/wry`** — локальная копия wry с патчем для Windows 7. Не обновлять wry без переноса патча (`src-tauri/vendor/README.md`, `docs/windows7.md`).
- **Комментарии** — только там, где нужна причина решения (бизнес-правило, неочевидный выбор). Не пересказывать код.
- **Миграции.** Изменения схемы и одноразовые правки данных — только миграцией в `storage/db.rs`:
  идемпотентно, в транзакции, с записью в `app_migrations`. Перед миграцией, которая меняет данные, делается резервная копия
  (`timetable-backup-<дата>.db.zip`). Существующая база пользователя должна открываться новой версией без ручных действий.
- **Журнал (`logs/app-<дата>.log`).** Пишем операции, которые меняют данные или показывают результат, и ошибки с кодом и причиной.
  Клики и навигацию не пишем. Журналы прошлых дней сжимаются в `app-<дата>.log.zip`, хранятся 2 года.
- **Сортировка по-русски.** Имена сортируются через `repo::sort_key` (без учёта регистра, «ё» как «е»), а не `ORDER BY` в SQL.

## Важные правила предметной области

- Ставка преподавателя: `rate > 0` и кратна 0,25. Целевое число занятий: `rate * 12`.
- Лимит `teacher_count` — свойство слота: все пары слота имеют один лимит. Меняется командой `set_slot_teacher_count`,
  не может быть меньше числа уже назначенных. Число назначенных — уникальные преподаватели слота.
- Снятие с единственной пары оставляет пустую заглушку с тем же лимитом. Назначение сначала переиспользует пустую заглушку,
  иначе создаёт новую пару. Факультеты строки (слота) — общие для всех пар слота.
- «Очистить назначения» снимает всех преподавателей, пары остаются заглушками с лимитом и факультетами.
- Удаление строки слота — удаление всех её пар со связями, с подтверждением по числу пар и назначений.
- Время пары — строго `ЧЧ:ММ`. Пары одного дня не пересекаются, точный дубль запрещён, начало раньше конца.
  Без признака «нестандартное время» допускаются только стандартные пары ТулГУ (95 минут), список хранится в `schedule.rs`.
- Направление: в API `0` означает «без направления», в базе — `NULL`. Преподаватель без направления назначить нельзя.
  Преподаватель с архивным направлением тоже не назначается (`direction_archived`), пока направление не восстановлено или не сменено.
- Отвязка преподавателя от семестра снимает все его назначения в этом семестре. Подтверждение показывает число назначений,
  после снятия — уведомление с тем же числом. Архивный преподаватель остаётся в расписании со своими назначениями.
- Гостевой преподаватель может быть привязан только к одному семестру. Новый семестр получает всех неархивных и негостевых преподавателей.
- Даты семестра — `YYYY-MM-DD`, начало не позже конца.
- Удаление справочников — **архивация** (`isArchived`), не физическое удаление. Восстановление — из архива.
  В интерфейсе кнопка подтверждения называется «В архив».
- Архивные направления и факультеты остаются видимыми с пометкой «(архив)» в сетке и экспорте.
- Экспорт XLSX: день, время, факультеты, «занято/лимит», затем колонки привязанных преподавателей по ФИО.
  Архивный преподаватель не уходит в конец колонок, порядок не зависит от статуса архива.

## Совместимость

- Go-версия больше не поддерживается. Совместимость со схемой и JSON Go не нужна.
- База пользователя: `~/.tulsu-pe-timetable/timetable.db`. Изменения схемы допустимы только миграциями (см. выше),
  старая база должна открываться.
- Конфиг: системная папка конфигурации, `tulsu-pe-timetable/config.json`. Ключ `dbPath`. Поле `theme` больше не используется
  (в старых файлах игнорируется). Путь к базе через API не меняется.

## Визуал

- Дизайн не менять без причины. Стили берутся из `legacy-go-version` и уже сложившихся компонентов.
- Только светлая тема. Классы `dark:` и переключатель темы не добавлять.
- Шрифт Nunito подключён из `@fontsource/nunito` (latin и cyrillic, веса 400–700) в `frontend/src/main.ts`.
- Таблица расписания: день, время, количество преподавателей и факультеты — липкие колонки слева. Ширина фиксирована
  только у первых трёх, колонка факультетов по содержимому.
- Не ставить лишние линии и разделители в формах: используй отступы. Списки внутри форм — без `divide-y`.

## Работа с пользователем

- Отвечай по-русски, кратко, по делу.
- Не спрашивай разрешения на то, что явно входит в задачу. Спрашивай, когда нужен запуск GUI,
  коммит, решение о дизайне или потенциально разрушительное действие.
- Пользователь не любит фоновые процессы и длинные таймауты. Если он прервал команду — остановись и спроси.
- Про результат пиши честно: что проверено (`pnpm check`, clippy, живой запуск), что нет.

## Открытые вопросы и пустые места

- Гостевой режим создания преподавателя в UI не реализован — так и было в оригинале.
- Живой запуск после последних правок не проверен: экран расписания (липкие колонки), стартовые диалоги, CSP в WebView2 109.
- Экспорт в Excel проверен пользователем на macOS. На Windows и LibreOffice не проверялся.
- Windows 7 работает (установка и запуск на VM, 2026-10-17). Открытые пункты: рабочий ПК кафедры, лицензия Microsoft на Fixed Version,
  функции WebView2 вне базового сценария, первый прогон шага импортов в CI. Подробности — `docs/windows7.md`, раздел 7.2.
- Ветки `main` и `origin/main` могут расходиться по SHA. Синхронизацию делает владелец, без сброса без просьбы.
